## 1688 图片上传兼容修复（1.0.3，2026-11-12）

- 调整为用户点击后同步打开 1688 图片搜索页，再以 `Accept: image/jpeg` 请求原图。图片 CDN 若仍返回 AVIF/WebP，则由浏览器离线解码并转换为 JPEG，再下载到本地供用户上传；转换失败会在面板提示原因。
- 界面明确提示用户在 1688 点击“以图搜款”并选取下载文件；不把打开上传页或下载成功描述成搜索已提交。原始图片只在本地浏览器处理中，不经过扩展后端。
- 自动验证包含 AVIF 转 JPEG、JPEG 文件魔数、1688 上传页 URL 和本地夹具商品页。真实 1688 上传需要用户会话，不能由离线夹具证明；实际结果应以手动上传的同图搜索结果验收。

## 1688 真实控件结构适配（1.0.7，2026-11-12）

- 1.0.6 实际页面超时，根因有三项：顶部入口与预览提交是无 role 的 div；文件输入框 accept 为扩展名列表而非 image/*；全页取最后一个文件框会误入中部加号。旧夹具使用 button 和 image/*，未覆盖真实结构。
- 从真实在线页面及公开 `https://g.alicdn.com/1688-search/pc-image-search/0.0.29/js/213.js` 核对结构。现在仅选择 `.search-image-upload-container .image-upload-button-container input[type=file]`，接受 JPEG 扩展名列表；等待同顶部容器中 `.copy-image-container .search-btn` 文案从上传中切换为搜索图片后提交。
- 删除全页最后文件框兜底；无匹配时明确提示“顶部文件框”或“上传完成后搜索图片”超时。已有图片数据时提供可点击的 JPEG 下载回退。
- 回归夹具按公开组件结构提取（未复制或执行原站脚本），覆盖 DIV 控件、扩展名 accept、清空 input、异步上传和错误加号入口。真实商品 HTML 回放复用该夹具。
- 独立 Chromium 中已完成真实1688上传与搜索：URL含新 imageId，页面1/6并展示包含Persil的商品结果，截图与报告在 `test-results/1688-online-auto.*`。eMAG 来源使用公开商品图夹具，不宣称已接入用户浏览器登录态，也不将搜索结果当成同款鉴定。
